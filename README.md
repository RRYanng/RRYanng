### 🧠 Things I've been thinking about

- **Output structure matters more than prompt wording.** Most of my "prompt engineering" time is spent on JSON schemas and output shape, not clever instructions.
- **Data integrity > data volume.** Deleted 272 courses from Everyone 72 because one wrong par value cascades into a broken product. The app looked more impressive with 500+ courses. It's more trustworthy with 262.
- **Human-in-the-loop isn't a fallback, it's the product.** MakerLens ships 95% automated, but the last 5% (a human deciding "this hook genuinely sees the founder") is what makes it work.
- **Build-in-public means exposing your process, not exposing other people.** When shipping MakerLens publicly, I had to anonymize 21 real founders' product critiques that were sitting in my local pipeline — none had consented to being public, and the right thing was more work than the code itself.
